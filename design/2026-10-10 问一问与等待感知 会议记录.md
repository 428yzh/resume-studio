## 二、问一问设计（已定）

### 会话模型

| # | 结论 |
|---|---|
| 1 | 粒度 = **每学习单元一个会话**，key `{skill_id}__{unit_key}`（`unit_key` 同既有约定） |
| 2 | 状态住在**前端 store**（`Record<key, RoomState>`，照 feynmanStore 的房间隔离写法）；**每单元单例，点开不重载** |
| 3 | **v1 只存内存，不落库**，刷新即消失；单用户量级，存储/并发不是问题，将来要跨设备再说 |
| 4 | 服务端**无状态**：每次请求现拼上下文 = 技能名 + 技能备注 + 这块的图谱块（带 id）+ 笔记三栏原文 + 对话历史（截断后） |

### 开场（吸收复盘）

| # | 结论 |
|---|---|
| 5 | 打开 = `messages: []` 的特殊请求（`POST /api/skills/:id/notes/chat`）；agent 先读笔记：**轻点评 + 指不足**，不判分、不落库（结论 27 不变） |
| 6 | **没写完也读**：prompt 写明「笔记可能还没写完，按现状读，别催补全」 |
| 7 | **空笔记门槛保持**：笔记为空时不开场 —— 不拿空笔记去烧 AI 调用 |
| 8 | **无缺口分支**：不硬凑缺口、也不宣布通过（结论 21「每个探测器只能证伪不能证实」；结论 4「验证归费曼」）。给两个出口：① 换个角度再问你两句 ② 去费曼房间讲一遍。v1 只给文字引导，费曼深链等 D13 |
| 9 | 开场要短：**稍微点评就好**，禁止小作文（实证：prompt 放开时模型写 2000+ token 长文，格式还漂移） |

### 实时性

| # | 结论 |
|---|---|
| 10 | **对话是记录，语境是实时的**：每次请求现读最新笔记 —— 没有「把新笔记给 agent 看」这个动作 |
| 11 | 发请求前先 flush `saveCornell`（400ms 防抖），不留「问的是旧笔记」的空窗 |
| 12 | 抽屉里一行静态小字：「它每次都会读最新笔记 —— 改完直接问就行」 |
| 13 | **不自动重评**：打开抽屉不自动重跑 —— 成本 + 监视感 + PRODUCT 原则 4（不替用户做决定） |
| 14 | 「重看一遍」= 对话里说一句就行，不加按钮 |

### 入口形态（按钮 → 两态）

| # | 结论 |
|---|---|
| 15 | 未被用过：「问一问 · 让它先读一遍这块笔记 →」安静一行（不是按钮 —— 按钮有触发的意味） |
| 16 | 用过之后：「问一问 · 聊过 N 句 · 继续 →」，点击**零请求**，直接展开已有对话 |
| 17 | 抽屉标题「问一问」；**去掉 L1–L5 LevelBadge** |

### 错误处理

| # | 结论 |
|---|---|
| 18 | 开场失败 → `AIErrorBox` +「再试一次」（沿用既有套路） |
| 19 | 回复中途断 → **保留已出的半截文字** + 错误行 +「重试」重发那条（比 feynmanStore 的「清空」进一步） |
| 20 | **不引入自动重试**：全项目无错误自动重试先例；自动重试 + 不吭声 = 新的静默失败。注：`Agent.call` 有一条「防截断」自动重试（`finish_reason == length` → max_tokens 翻倍，上限 8192），性质是防截断不是防报错，保留 |

### v1 范围外

- 不联网、不带工具调用（全仓唯一工具调用先例在 `job_service.search_jobs` —— Anthropic 兼容端点的 `web_search` 服务端工具；将来要给问一问「查资料」就从那搬）
- 不做费曼深链（D13 后）
- 不落库

## 三、删除清单（复盘端点全家）

删掉「第二条读同一份笔记的 AI 路径」；能力不消失，搬进问一问开场。

| 删 | 留 |
|---|---|
| `POST /api/skills/:id/notes/review` 路由 | `_render_cornell()`（问一问拼语境复用） |
| `review_notes()` / `_REVIEW_SYSTEM_PROMPT` / `_sanitize_review` | `skill_notes` 表与既有笔记 |
| `NoteReviewRequest` / `NoteReviewResponse` / `NoteGap` 三个 schema | 前端笔记区位置（入口原地变形态） |
| 前端 `runReview` / `NoteReview` 类型 / review state / LevelBadge 分支 | 错误处理套路（`AIErrorBox`） |
| TC-REVIEW 系列用例 → 改写成 TC-CHAT 开场用例 | 结论 27「不判卷、不落库」 |

**删除依据（实证）**：2026-10-10 审计日志 —— 模型输出 JSONL（首行一个对象、后面每行一个 gap），`_parse_json_defensive` 兜底把整段重新解析失败 → 返回 `{}` → 前端显示「没挑出缺口」。JSON 单包协议 + 强制结构 = 格式一漂全丢；改成对话后没有 JSON 可漂。

## 四、等待感知（状态流取消后的替代）

- **状态流取消**：learning-plan / explain-topic 不转 SSE、`review_pipeline` 不加 `on_stage`、不抽 `readSSE` —— 端点协议不动，改动面为零
- **替代 = 真实的时间 + 真实的说明**：
  - 新组件 `ElapsedTime.tsx`：吃 `startedAt` 时间戳，每秒自刷「已等待 42 秒」
  - **锚「请求发出时刻」，不锚组件挂载** —— 「收起后台等待、再打开」是明说的设计动作，锚错会归零
  - 文案升级：「生成需 1-3 分钟」→「生成 + AI 自检通常需 1-3 分钟」—— 是对**固定管线**（生成 → 双评审 → 必要时重写）的静态描述，不是实时阶段播报
  - 三处：`LearningPanel` / `SkillLibrary` / `SkillWorkbench`
- **明确不做**：假阶段文字轮播、假进度条、百分比 —— 没有信号支撑，演出来的
- 可选兜底（未拍板）：超 3 分钟换「比平时久，还在继续」

## 五、实施顺序
