### D1 · 卡片正面还留不留自评滑块 —— ✅ 已按推荐落地 2026-10-03（见文末）

**背景**：卡片化之后滑块占卡片中间一整条，而整张卡是可点击展开的。点击卡片中心会落在滑块上改自评，而不是展开。实测踩到过一次（把 `pi Agent源码讲解` 从 `null` 改成了 `50`）。

**这跟遗留 L11「自评滑块保留与否」是同一个问题**，只是现在有了具体的痛感。

**我的推荐**：滑块从卡片正面移走。依据是结论 20 —— 自评不该是入口，该是**下注**（预测—揭晓）。卡片正面留给图谱三要素（覆盖率 / 状态 / 单元数），自评挪进展开区。

**影响**：⑧ 技能库卡片定稿。

**落地（2026-10-03）**：滑块整块移进展开区顶栏（`{技能名} · 详细信息` 那一行右侧，`data-testid="skill-proficiency"` 保留）。
卡片正面从此只有名字/分类/来源、图谱状态徽章、覆盖率占位、备注、生成图谱与编辑删除 —— 点卡片中心只展开。
E2E 顺带修掉一个**一直存在的偶发**：原用例拖完滑块立刻 `reload()`，把在途的 PUT 掐掉，
断言靠本地 state 侥幸通过；改成 `waitForResponse` 等 PUT 落地再刷新。
（教训：本地 state 已经更新 ≠ 已保存。这类"看着像保存了"的竞态，测试也会被一起骗过去。）

### D2 · 图谱出题和现有 `/quiz` 出题是一套还是两套

**背景**：原遗留 L5，当时你说「再说吧」。分数要落在图谱节点上（结论 12），就得知道题挂在哪个节点 —— 所以这件事在 ⑥ 之前必须定。

**我的推荐**：**复用**。给 `generate_quiz_questions` 加可选 `node_id` 参数，图谱单元出题时传，普通刷题时不传。另起一套会让两个出题入口打架（同样的 `/api/questions` 表、同样的判分路径，两套 prompt 迟早不一致）。

**阻塞**：⑥ 分数落回节点。**可以推到 ③ 之后再定，但别再往后。**

### D3 · 三个调用点的 `max_rounds`：开 `=1` 还是删掉评审调用

**背景**：`review_pipeline` 的默认值是 `max_rounds=0`，而三个调用点（`generate_learning_guide` / `explain_topic` / `generate_learning_plan`）**全部用默认值**。代入循环后：生成一次 → 评审两次 → 算出的 `bad` 只用来打日志 → 返回没过审的那版。三个调用点还都是 `content, _ = ...`，verdicts 也扔了。

**所以今天这 3 个生成函数，每次调用额外花 2 次 AI 调用跑评审，对产出零影响。** 加了评审和不加，用户拿到的内容一模一样。

反讽的是 `test_review_pipeline.py` 里 `max_rounds=1`/`2` 测得挺好 —— 棘轮、回滚、反馈注入的逻辑是完整的，测试钉住了它，只是生产从没打开过。CLAUDE.md 写的「不合格则反馈增量注入重新生成」描述的是一个默认关闭的能力。

**成本结构**：

| | AI 调用次数 |
|---|---|
| 现在（`max_rounds=0`） | 1 生成 + 2 评审 = **3** |
| 开 `=1`，首轮过审 | 1 + 2 = **3**（`bad == 0` 直接 break，**不加钱**） |
| 开 `=1`，首轮没过 | 2 + 4 = **6**（**只在真需要重写时翻倍**） |

**我的推荐**：**先开 `=1` 跑对比** —— 同一批输入，把开/关的产出并排摆出来，再把 token 和耗时差量出来。这是回答「multi-agent 值不值」的唯一办法：如果连「评审一次、不合格重写一次」这个最小闭环都换不来肉眼可见的提升，更激进的架构就更不用谈。

**要么打开，要么删掉评审调用。挂着不开是纯亏。**

### D4 · 自评与图谱分数的「落差」怎么算

**背景**：原遗留 L11 后半。自评是技能级的一个数，图谱是一张分布图 —— 两者不同构，相减没有天然定义。

**我的推荐**：落差 = 自评 − min(证据)，**且只在有证据的节点上算**。依据结论 21（每个探测器只能证伪，不能证实）。没有证据的节点不参与，否则「未测」会被算成「不会」。

**阻塞**：⑥ 的仪表盘语义。

### D5 · ⑤ 复盘的输出结构

**背景**：原遗留 L3。现在 `grade_essay_answer` 是「面试评分专家」+ `{score, feedback, reference}`，而定位要改成**让 AI 看你的答案、理解你的思路、指出思维模式上的不足** —— 分数不是重点，**缺口清单**才是。

**我的推荐**：
- 等级沿用费曼已有的五级（混沌 / 字面 / 关联 / 重构 / 辩证），两处语义对齐（顺带解决 L4）
- 缺口清单 `[{node_id, gap, suggestion}]` —— `node_id` 正好能落回图谱，⑥ 直接可用
- `reference_answer` 在笔记场景**留空**：线索问题没有标准答案，是 AI 自产自销
- 产出喂仪表盘时算「AI 判定」（0.8），不是「客观判分」（1.0）

**阻塞**：⑤。

### D9 · 笔记 key 从 `step{n}` 换成图谱节点 id

**背景**：localStorage key 是 `cornell__{skillId}__step{n}`，`n` 是学习计划里的步骤号。② 之后重生成图谱/计划会变成常事，旧笔记会**静默指向别的内容** —— 今天就有这个问题，只是没人重生成过所以没暴露。

**我的推荐**：**换**。④ 搬服务端时顺手把 key 改成节点 id，根治。不换的话，将来每次重生成都是一次静默数据损坏。

**阻塞**：无（④ 的顺带机会）。

## ⚪ 已由我定夺（供反对）

这些是实现细节，不需要你拍板，但列出来给你否决的机会。

| # | 决定 | 理由 |
|---|---|---|
| A1 | 图谱独立成 `knowledge_graph` 列，不塞进 `learning_plan` JSON | 卡片要「生成过没有」这个布尔，独立列一次 SELECT 就够，嵌套 JSON 得逐行 parse |
| A2 | 图谱生成**不进评审管线**，用结构校验器代替 | 树的容量约束是**代码可判定的**，烧 2 次 AI 调用去查一个 for 循环能查的东西不值。评审 agent 留给判不了的（讲解写得好不好） |
| A3 | 节点 id 由**服务端**发号（`1 / 1.2 / 1.2.3`），不让模型自己编 | 模型编号会重复会漂，而这 id 是分数落点和笔记归属的锚 |
| A4 | 图谱结构校验两次不过 → **接受 + 标 `degraded` + 带 issues** | 不静默接受一棵超 3 层的树（父节点累加会算错），也不因为结构瑕疵就整个丢弃 |
| A5 | 已生成图谱**不给「重新生成」按钮** | 节点 id 是分数和笔记的锚，重生成会把它们全冲掉。真要重生成得先设计迁移 |
| A6 | `SkillResponse.has_graph` 只暴露布尔，不给树 | 列表页要的是「生成过没有」；整棵树等展开时单独 `GET /graph`，不随列表 N 倍膨胀 |
| A7 | 新建技能表单不带 `proficiency` | ① 已定：没自评过就存 NULL，用预填的 50 冒充自评是假数据 |
| A8 | **学习计划的单元数由图谱顶层节点数决定**，不再由 `required_level` 拍脑袋定 | 图谱已经编码了这门技能的粒度。掌握程度改去调**每单元多深**（了解=扫盲 / 精通=原理与排错），不把同一块内容重新切一遍。了解档允许把相邻顶层节点合并（实测 5 顶层 → 4 单元）。**副作用**：`_PLAN_SYSTEM_PROMPT` 里「精通 → 6-10 步」那条没了 —— 4-6 个顶层节点最多切出 6 个单元 |
